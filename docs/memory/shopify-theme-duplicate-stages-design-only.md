description: A Shopify theme duplicate stages THEME CODE only; pages, product copy, policies, images and app config go live on save whatever theme they are edited on

---

Learned on instawarm (2026-08-15), applies to every store fix engagement. Pages, product descriptions, policies, images, metafields and app configuration are store data shared across all themes, so they change the LIVE site the moment they are saved, whichever theme is published. Only theme code and section settings actually stage on a duplicate.

**Why:** promising a client "review everything on a preview link before it goes live" is only keepable for the theme-code fraction of a fix package. Promise it for copy fixes and you either break the promise or build everything twice.

**How to apply:** before promising staged delivery, classify every item of the package as theme-code (stages) or store-data (goes live on save). Founder ruling on instawarm: one pass on the live store plus a change list; completion means "live and listed", never "preview approved", so payment on completion cannot hang on a client-controlled approval loop.
